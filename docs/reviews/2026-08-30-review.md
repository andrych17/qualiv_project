## 4. Temuan Bug, Edge Cases & Analisis Risiko

### 4.1 Prioritas Tinggi (HIGH)

#### 1. Hardcoded Expense Account ID di Cross-Module AP Handshake
- **File:** `app/Modules/Purchase/Services/InvoiceMatchingService.php:227`
- **Kode:** `'expense_account_id' => 1`
- **Dampak:** Saat Purchase Invoice disetujui dan membuat tagihan AP di Accounting (`createBill`), akun beban/clearing di-hardcode ke ID `1`. Pada tenant yang memiliki Chart of Accounts kustom (di mana ID 1 bukan akun beban AP clearing), pembuatan bill akan gagal atau salah catat jurnal.
- **Solusi:** Ambil akun secara dinamis melalui `ConfigConst` (misal `PURCHASE.DEFAULT_EXPENSE_ACCOUNT`) atau ambil akun beban aktif pertama dari database.

#### 2. Test State Isolation di Central Database saat Batch Run
- **File:** `tests/Concerns/SetsUpTenant.php:18`
- **Kode:** `protected $connectionsToTransact = [];`
- **Dampak:** Karena `connectionsToTransact` dikosongkan, `RefreshDatabase` melewati rollback transaksi pada koneksi central default. Record tenant dari test sebelumnya tertinggal di tabel `tenants`, sehingga saat `php artisan test` dijalankan secara batch, test seperti `CentralTenantCreateTest` dan `GenerateCentralInvoicesCommandTest` mengalami false positive / failure (padahal jika diuji satuan per file, keduanya 100% PASS).
- **Solusi:** Bersihkan record tenant central pada `tearDown()` di `SetsUpTenant` atau gunakan scope asersi per `tenant_id`.

---

### 4.2 Prioritas Menengah (MEDIUM)

#### 1. Risiko Kolisi Sequential Tenant ID Auto-Increment
- **File:** `app/Modules/Central/Services/CentralTenantService.php:188`
- **Kode:** `$max = (int) Tenant::query()->orderByDesc('id')->lockForUpdate()->value('id') ?? 0;`
- **Dampak:** `orderByDesc('id')` pada PostgreSQL mengurutkan string. Jika ada ID tenant non-numerik (misal ID test `'pf1'` atau kode kustom), ID tersebut akan berada di urutan atas dan dievaluasi `(int)'pf1' === 0`, mereset kalkulasi `$max + 1` kembali ke `'001'`.
- **Solusi:** Filter hanya string numerik saat menghitung max:
  ```php
  $max = (int) Tenant::query()
      ->whereRaw("id ~ '^[0-9]+$'")
      ->orderByRaw('CAST(id AS INTEGER) DESC')
      ->lockForUpdate()
      ->value('id') ?? 0;
  ```

#### 2. Kebijakan Harga Unit pada Sales Return Replacement
- **File:** `app/Modules/Sales/Services/ReturnService.php:130`
- **Dampak:** Pada saat membuat Sales Order pengganti barang retur, pastikan terdapat flag apakah replacement bersifat klaim garansi (harga Rp 0 / FOC) atau berbayar dengan rate diskon asal agar pelanggan tidak ditagih ganda.

### 4.3 Dicek dan Bersih (Security & Compliance)

- **SQL Injection**: **Zero vulnerabilities**. Semua query sorting/filtering di-whitelist via `TableQuery::applySort()` dan parameter query ter-bind sempurna.
- **IDOR & Path Traversal**: Download versi dokumen DMS diverifikasi via scope akses folder; storage key menggunakan UUID.
- **Isolasi Multi-Tenancy**: Tidak ada kebocoran antar tenant. Tenant context selalu terpropagasi pada queue jobs dan API headers (`X-Tenant-Id`).
- **Integritas Transaksi**: Setiap write multi-tabel (Orders + Lines, Invoices, Ledgers) dibungkus `DB::transaction(...)`.
